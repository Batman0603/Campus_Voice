## F. Database review

Users optionally belong to a department. Department deletion nulls the user association but is restricted while questionnaires reference it. Questionnaires restrict creator deletion, while draft descendants cascade through sections, questions and options. Assignment relations restrict deletion of recipient, issuer and questionnaire. Submissions and answers restrict deletion of referenced records.

The migration SQL defines unique questionnaire/recipient pairs, one submission per assignment and one answer per submission/question. It also constrains section and question positions and option values. Those database constraints back duplicate detection. The configured migration-status result establishes ledger state. A freshly migrated disposable database matched the current Prisma schema. The configured database was checked for migration status only. The audit did not sample existing user records or change them.

## G. Missing and incomplete features

- CSV and PDF exports, shared authorization parity, MIME and attachment checks, suppression parity, formula protection, pagination and Unicode handling are unavailable on this branch.
- CampusVoice workflow pages, role navigation, editor, response and confirmation screens, dashboards and download controls are missing. Loading, empty and error interactions for those screens cannot be verified.
- Production privacy rules for repeated reports, sparse distributions and exact counts remain undefined. The five-response rule is a provisional lower bound.
- The CI workflow has no unit/integration test step. API coverage should add all six answer types, branching fixtures, zero denominators, approved reporting disclosures and concurrent state transitions.

## J. Final verdict

1. **Are Phases 1–5 fully implemented?** No. The matrix identifies missing exports and UI plus partial backend verification and a branching failure.
2. **What was tested?** Static quality checks, schema validation, migration ledger, dependency audits, 37 repository unit tests, two focused in-memory checks, 20 isolated API check groups and a headless homepage smoke test.
3. **What is incomplete?** Exports, custom workflow UI, disclosure rules, authoring/submission consistency, and full concurrency and end-to-end coverage.
4. **Are there authorization vulnerabilities?** Static review found questionnaire existence disclosure and a potential department transfer policy gap. Role and object guards are present. Credential throttling was not identified.
5. **Are student data adequately protected?** The APIs reviewed exclude identities and raw answers from reports. Exact counts, repeated queries and sparse option buckets prevent a production privacy sign-off.
6. **Are analytics accurate?** Supplied unit fixtures pass. Full population accuracy and privacy-aware reporting require more fixtures and policy verification.
7. **Are exports secure and functional?** Export functionality is missing, so download security and correctness cannot be verified.
8. **Are there integrity issues?** Yes. Cross-table association and concurrent lifecycle invariants are incomplete despite strong uniqueness and FK constraints.
9. **What must be fixed before Phase 6?** Address high findings first, then complete exports and UI scope, validate supported reporting policies, and run build and regression checks.
10. **What should be tested manually?** Role changes, session invalidation, department transfers, all authoring and conditional branch cases, keyboard/accessibility and mobile behavior, privacy-sensitive reports, and future CSV/PDF downloads opened in target clients.
